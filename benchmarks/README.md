# Imaging benchmark

The benchmark runs each engine in an isolated local Chromium process. The input is the exact same generated Part 10 file for all engines in a scenario. A reference result must pass before a timing can be used. The monochrome comparison checks the original signed sample. Cornerstone3D may return a pre-scaled sample, which the benchmark normalizes using the object's affine rescale. The color comparison checks three independent original frames against the same decoded RGB tolerance. RayKit also compares WebGL2 output with its CPU reference at native sample centers and analytic fractional coordinates.

```sh
npm run fixtures
npm run build:web
npm run benchmark:build
npx playwright-core install chromium
npm run benchmark
```

`RAYKIT_CHROMIUM` selects a local Chromium executable. `RAYKIT_REPEATS` controls monochrome repetitions and `RAYKIT_CINE_REPEATS` controls long-cine repetitions. `RAYKIT_ENGINES` selects a comma-separated subset. Results are written to `benchmarks/results/compare.json`. The test records process RSS through Linux `/proc` and Chromium's process information protocol. Browser and GPU process RSS are separate readings. GPU texture sizes are estimates based on dimensions and formats. WASM capacity includes its buffers, decoder scratch and retained dataset. RSS is a sampled high-water reading that can miss allocations released between polls.

The cold run starts on a new page and browser process. The warm run recreates the source and viewport within the same page. The runner separately reports module loading, file readiness, opening and the first original-image observation. A browser may coalesce draws. Interaction results use each engine's rendering event or animation tick to time presentation. Cine uses a separate source-frame cadence. Failed openings and sample mismatches retain their diagnostics without contributing to timing statistics.

The DICOM fixtures are generated by `cargo run --locked --release -p raykit-core --example generate-fixtures -- fixtures/generated --long-cine`. `benchmark-signed12` uses a conventional High Bit and sign extension in the allocated word. Additional `signed12` files exercise nonstandard historical packing. No real imaging records are used.

DWV and Cornerstone3D are benchmark-only npm dependencies. The WebGPU program is a monochrome comparison candidate. Its benchmark requires a WebGPU-enabled Chromium profile. The default SDK renderer supports WebGL2 and can fall back to the Rust CPU reference.
